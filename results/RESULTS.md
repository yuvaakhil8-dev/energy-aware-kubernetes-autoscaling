## How to read the headline tables

The experimental unit is one run (workload, seed, strategy). Tick-level observations are aggregated inside a run first; ticks are not treated as independent samples. Missing values (including energy per served request when zero requests were served) are reported as `n/a` and are never replaced with an artificial denominator. Energy per served request is always shown next to energy per offered request and the drop rate, because a controller can look efficient merely by serving less traffic.

Confidence intervals are percentile bootstrap intervals over runs. Paired differences are strategy minus baseline; a negative difference is favourable only for metrics where lower is better (all metrics in this table). The Wilcoxon signed-rank test uses independent seeds as blocks and is Holm-adjusted within each workload x baseline family.

## Guardrails

- Simulation results do not establish production behaviour.
- The `hpa_formula` baseline is a simulated replica formula, not the native Kubernetes HPA controller.
- `cpu_threshold` is the legacy 80/30 rule, not HPA.
- The static strategy's apparent efficiency can be an artefact of unmet demand.
